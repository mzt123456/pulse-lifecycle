# 故障诊断

## 什么时候用

用户描述现场现象（"下井之后地面收不到脉冲信号"、"阀芯有点卡，声音不对"），
想知道可能原因和怎么处理。

## 流程

1. 用户给了设备编号时，先 `query_equipment` 确认设备存在；编号查不到就如实说明，不要继续往下编。
2. 调 `query_fault_history` 查这台设备或这类故障的历史记录（现象、原因、处置）。
3. 调 `diagnose_fault` 走案例检索与归纳——这是系统自建的检索增强能力，返回的每条结论都带案例依据。
4. 把两边合起来讲：最可能的原因排在前面，再给分步处置。

## 必须遵守

- 每条原因和处置都要能对应到具体案例或历史记录；对不上的不要写。
- 检索不到相似案例时直接说"知识库里没有相似案例"，
  不要用通用经验补齐——这条是硬约束，宁可少说也不能编。
- 涉及高温井、打压试验、高压拆装时，处置建议前加一句现场安全提示。
- 判断不了就明说要补什么信息（仪器类型、部位、参数），不要含糊其辞。

## 输出格式

结论一句 → 可能原因（1-3 条，每条注明依据来自哪条案例）→ 建议处置（分步骤）
→ 还需补充的信息（判断不了时）
